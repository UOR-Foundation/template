# Hosted SDK storage regression

A standard Ubuntu runner failed while extracting the locked SDK's Rust layer:
`docker: failed to register layer ... no space left on device`, exit 125.
The repository acceptance command had not started.

The regression test `hosted_sdk_disk_is_prepared_before_image_pull` was added
first. In the existing SDK, `cargo test --locked --offline -p xtask
hosted_sdk_disk_is_prepared_before_image_pull` failed with `prepare hosted
runner storage before pulling the large SDK`.

The workflow now removes only unused preinstalled Android, .NET, Haskell and
CodeQL tools on GitHub-hosted Linux runners, before the SDK image pull, and
prints filesystem availability. It preserves Docker storage and caches, the
SDK digest, the complete acceptance command and native architecture coverage.
Self-hosted machines do not enter the removal branch.

The same focused test passes after the change. All 19 xtask tests and
`prismpm template check` pass inside the existing immutable SDK. The template
lock was generated by `prismpm template update`, naming policy input commit
`87d1e83364e3932a6205702da5ba3d78f2e10a74` as required by TEMPLATE-CONTRACT.md.
Actual fresh-runner extraction is established by the upstream/downstream CI
executions; local tests alone do not measure hosted-runner free space.
